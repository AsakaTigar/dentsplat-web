# DentSplat：方法论与核心代码

> 一台不装任何软件的电脑，打开一个网址，就能看到一份可交互、可核查的牙科三维模型；
> 模型里的每个数字，都能用仓库里的脚本重新算出来。

这份文件把项目的方法论和全部核心代码放在一处。代码不是摘抄，是逐字节从仓库读出的原文——每段都带路径、行数和 sha256，文件末尾的校验命令可以证明它与仓库一致。资产二进制、依赖、构建产物不在其中，它们由 §12 的命令重新生成。

生成与校验：

```bash
node tools/build-method-doc.mjs            # 重新生成本文件（写入 Downloads）
node tools/build-method-doc.mjs --verify   # 证明本文件与仓库逐字节一致，且没有过期
```

## 1. 方法论：先定判据，再写代码

### 1.1 要证明的三件事

这个项目的目标不是"做一个好看的牙科 demo"，而是用可核查的方式回答三个问题：

1. **牙科数据 → 3DGS 的链路真的能跑通吗？** 不是示意图，是同一份数据从 CBCT 分割（或 IOS 网格）一路走到浏览器里可渲染的容器文件，并且每一段都有字节级证据。
2. **3DGS 相对 Mesh / 体渲染的取舍是什么？** 用同一台机器、同一份构建量出来的数字说话：体积、保真、单遍耗时、随分辨率的伸缩行为。
3. **它和实验室的临床问题怎么接上？** 牙位定位、CBCT 高效阅读、可核查证据——不是画饼，而是把每个临床问题映射到一个已经实现的交互，并明确哪些结论还缺真实病例。

### 1.2 为什么是 3DGS，而不是 Mesh 或体渲染

- **Mesh**：表面网格必须先把点云三角化。牙列的邻接面、龈缘、根分叉处拓扑复杂，三角化要么丢细节要么爆面数；而且加一个"半透明看神经管"的功能就要重做材质与排序。3DGS 的基元本身就是各向异性的高斯椭球，半透明是它的原生表达，不是后处理。
- **体渲染**：CT 体数据逐步光线步进，视觉上最接近放射科工作站，但每帧成本与体素量绑定，浏览器里很难同时做到"整牙列 + 六层语义 + 60 fps 级交互"。
- **3DGS**：把场景压成几十万个高斯，单遍渲染一次 draw call；代价是显存与排序，好处是保真与交互成本低，而且**语义可以随几何一起走**（见 §4）。

这个取舍不是信仰，是测出来的：剪枝后 30,232 个 splat、609,126 B 的文件，在浏览器回读像素上与完整包相比整帧 PSNR 21.82 dB、掩膜内 17.60 dB；单遍 GPU 0.5–2.9 ms 且从 640×360 到 2560×1440 几乎不变（`MEASUREMENTS.md` §3–§4）。

### 1.3 为什么在浏览器里

评审当天发一个链接就能打开，不给对方制造安装负担；同时浏览器是最苛刻的部署环境——如果它在这里能跑，桌面端只会更宽裕。代价是只能拿到 WebGL2 的能力边界，这一点在 §5 的仪器学里会再出现一次。

## 2. 五条不可让渡的规则

这五条不是口号，每一条都在仓库里有对应的代码或闸门。

**① 不编造任何数字。** 所有对外数字来自三处：浏览器内探针的 JSON 回读（`captures/*.json`）、离线链路的产物（`tools/out/cbct_route/*`）、或对产物重新哈希/重新计算。没有第四种来源。文件里出现的每个数值都能被 `npm run test:claims` 重新推导。

**② 合成资产必须常驻标注。** 当前几何按公开数据集的统计规律生成，颜色与病灶是程序化的。界面上常驻 `SYNTHETIC PREVIEW`，一页简报、演示视频的片头都带同一标注。标注不是免责声明，是数据来源的一部分。

**③ 未测得的写"待测"，不进正文结论。** 例如"低端集成显卡与远程桌面"未实测、"阻生智齿是否压迫神经管"只是可做的交互而非结果、Blender 渲染与真实训练产物后处理从未运行。这些句子出现在简报、视频片尾和 `MEASUREMENTS.md` §9，三处措辞一致。

**④ 字节可复现。** 同一条离线链路重跑必须逐字节相同。做不到时，先找原因再改代码：本项目因此删掉了容器里嵌入的 `converted_at` 时间戳、把元数据里的路径统一成仓库相对路径。46 项断言里有一项就是"重跑后 sha256 相同"。

**⑤ 闸门必须能被证伪。** 一个从不报警的检查等于装饰。每个关键闸门都配负例：标签同步闸用 `FLIP_ROWS` / `SCRAMBLE` 构造错位输入；一页简报闸用 300 mm 填充物证明它会翻页；视频卡片闸用 400 px 填充物证明贴合标记会消失；文档数字闸用 23 条变异逐条改坏一个数值，要求**指名**报错。见 §7。

## 3. 数据契约

### 3.1 坐标系与单位

右手系、Y 轴向上、**1 个场景单位 = 1 mm**。上颌在 +Y，唇侧在 +Z，患者的右侧在 −X。这条契约写在 `src/engine/Viewer.ts` 的注释里，也写在 `pipeline/NOTES.md` 中；离线链路产出的 PLY 在导出前必须过这一关，否则界面上的毫米测距没有意义。

### 3.2 层字节表

`layerId` 是逐 splat 的一个字节，取值与流水线常量逐字节一致：

| 值 | 层 | 值 | 层 | 值 | 层 |
|---|---|---|---|---|---|
| 0 | 牙龈 gingiva | 3 | 牙槽骨 alveolar | 6 | 牙髓 pulp |
| 1 | 牙体/釉质 enamel | 4 | 神经管 nerve | 7 | 上颌窦 sinus |
| 2 | 牙根 root | 5 | 其他 other | 8 | 修复体 restoration |

约定：**牙髓的 FDI 编号 = 对应牙齿 FDI + 100**，这样一颗牙的牙髓与牙体在同一个整数空间里可互相推导，不需要额外索引。CBCT 路线里"牙体"层别名 `teeth`，与 IOS 路线的 `enamel` 复用同一个字节值 1——两条路线在渲染端的语义因此是同一套。

`splat.flags` 的位定义：`1` 上颌、`2` 下颌、`4` 病灶、`8` 阻生、`16` 可做断面盖片。

### 3.3 数据来源与许可

- **Scene A**：Teeth3DS+ / 3DTeethSeg 风格的 IOS 表面网格（osf.io/um96h，CC BY-NC-ND）。
- **Scene B**：ToothFairy3 / ODIN2025 的 CBCT 分割约定（MICCAI 2025，532 例，0.3 mm，77 类，CC BY-NC-SA）。

两份数据都只用于研究与演示；产物里保留了来源与许可字符串，一页简报与视频片尾都标注了出处。

## 4. 容器：DSPK v1

### 4.1 为什么不用 ply / ksplat / spz

`ply` 没有语义位，标签只能放旁挂文件；`ksplat` 与 `spz` 为了 GPU 缓存局部性会把 splat **Morton 重排**——重排之后，任何"按行号索引"的标签数组都会静默错位。牙位一旦错位，整个"点选 26 号牙"的交互就是错的，而且错得很安静。

所以这个项目用一个自描述容器：**逐 splat 的语义（FDI、层、旗标）与几何在同一个平面流里、同一个顺序**，对齐是结构性的，不靠约定。

### 4.2 布局

小端序，128 字节定长头 + 变长 JSON 元数据 + 六个属性平面：

| 偏移/平面 | 内容 | 说明 |
|---|---|---|
| `[0,128)` | 头 | magic `DSPK`、版本、stride、count、bbox、log-scale 范围、meta 长度、64 B 名称、kind 位 |
| `[128,128+M)` | UTF-8 JSON | 名称、kind、牙位表、指标等自描述信息 |
| `pos` | u16×3 | 在毫米 bbox 内做 65535 级线性量化 |
| `rot` | u8×4 | 单位四元数映射到 [0,255]，解码后重新归一化 |
| `scale` | u8×3 | 对数空间在 `scaleLogMin/Max` 之间插值 |
| `color` | u8×3 | 由 SH 直流项得到的显示色 |
| `misc` | u8×4 | `[alpha, toothId, layerId, flags]` |
| `sh1` | i8×9 | 可选，系数 ×64 |

stride = 20 B（SH0）/ 29 B（SH1）。整包大小 = 128 + M + count×stride，解码器在读取前先校验 magic、版本、长度，截断即抛错而不是读出垃圾。这份实现在 `src/engine/dspk.ts`，与写入端 `tools/ply2dspk.ts` 共用同一套常量。

### 4.3 可复现性的两个坑

容器曾经因为两个字段而无法逐字节复现，都是"多出来的信息"而不是"少了信息"：

1. 元数据里嵌了 `converted_at` 时间戳——每次转换都不同。删掉。
2. 元数据里写了绝对 Windows 路径——换一台机器就不同。改成仓库相对路径（`disp()` 归一化）。

修完之后同一份 PLY 重跑两次，sha256 相同；这条被固化成流水线断言，而不是一次性的人工核对。

## 5. 渲染与交互

### 5.1 一次 draw call

每个 `SplatLayer` 是一份 `InstancedBufferGeometry` + 自定义 `ShaderMaterial`：几何体是 n 个 quad 的索引，属性平面直接上传为 instanced 属性，顶点着色器按协方差展开椭球、投影成屏幕空间的椭圆，片元着色器算高斯衰减。整层一次绘制。Full / Pruned 对比时是两层、两次绘制，各自独立。

深度排序在 **CPU** 做：每帧把 splat 中心沿视线方向投影成深度，在 400 mm 的范围内切成 16,384 个桶做计数排序，从远到近写进索引缓冲；相机基向量没变就不重排——这也是 `sortMs` 被单独记录的原因。

### 5.2 裁剪、剖切与高亮都在着色器里

三个交互不是"改几何再重建"，而是 uniform 驱动：

- **X/Y/Z 三轴剖切**：最多 4 个平面，片元着色器里做有符号距离，负侧 `discard`；在切面附近一个窄带里叠加盖片颜色（`uClipBand`），形成"断面"的视觉。
- **分层透视**：`uLayerAlpha[9]` 一个数组直接乘进 alpha，六个语义层的透明度分别可调。
- **点选高亮 / 隔离**：`toothId` 与 `uSelectedTooth` 比较，命中则换高亮色并做轮廓加粗；隔离则是把其余牙位写进 `uHiddenLo/Hi` 两个 32 位掩码后 `discard`。

这样做的好处是可测：着色器没有被黑盒库包住，任何一个交互的开关都能在页面探针里被断言成具体的像素或 uniform 值（`MEASUREMENTS.md` §6）。

### 5.3 不可见代理网格

毫米测距与牙位拾取不猜 splat 中心，而是对一份**不可见**的代理网格做射线求交——它由同一份数据生成，每个 mesh 以 FDI 命名。于是"点到的是 26 号牙的近中面，距 25 号牙 0.8 mm"这类结论有明确的几何参照，而不是"最近的高斯中心大约在哪"。

代价是测距是**水面距离**（surface-to-surface），不是质心距离；这一点在 `MEASUREMENTS.md` §9 里明确写着，不做模糊处理。

### 5.4 仪器学：为什么信回读，不信计时器

浏览器里的 GPU 计时器在隐藏窗口下会饿死：探针实测 `EXT_disjoint_timer_query_webgl2` 在完整包上 0/20 次响应（`MEASUREMENTS.md` §2）。于是主仪器改为**串行化的 1×1 回读**：把一次绘制同步到 CPU，扣除空转的同步延迟，得到 `netGpuMs`。两种仪器在同一场景下交叉验证过，结论是回读可用、计时器只能作为旁证。

这也是为什么 HUD 上那个 0.01–0.7 ms 的 `frameMs` 在隐藏窗口里没有意义——报告里从不引用它。

## 6. 测量定义

- **`netGpuMs`**：串行 1×1 回读测得的单遍 GPU 时间，减去同构造的空同步延迟。不是帧时间。
- **`paintedFraction`**：回读像素中"非背景"的比例，用来证明真的画了东西，而不是一片黑屏通过了所有断言。
- **PSNR（整帧 / 掩膜内）**：浏览器回读像素与参考渲染逐像素比较；掩膜内只统计被覆盖的内容像素，避免大片黑背景把指标抬高。
- **coverage gap**：剪枝前后点云在几何上的最近距离统计（p50 / p95 / max），用毫米表示。它回答"剪掉的 splat 让表面退了多少"，与像素保真互补。
- **对照组**：同一份数据、同一个相机、同一个渲染器；"同包重渲染对照"必须逐比特相同（PSNR 记为 999 dB），否则说明仪器本身不稳，先修仪器。

## 7. 证据制度

这一节是整个项目最花时间的部分，也是它区别于普通 demo 的地方。

### 7.1 探针的字节身份

页面执行的每一段探针脚本，都由自动化桥**先 fetch、再哈希、后 eval**，并把 launcher 的字节数与 sha256 写进 capture。因此一条 capture 不可能引用一个它没跑过的文件。`tools/nifti-wrapper.js` 就是这"薄薄的一层"，所有逻辑放在 `probe-nifti-launch.js` 与 `probe-nifti.js` 里，后者在 Node 端用 mock 跑过（23 项，含 `FLIP_ROWS` / `SCRAMBLE` 反例）才允许上页面。

### 7.2 文档与产物互证

`tools/verify-claims.mjs` 把文档当输入：从 `MEASUREMENTS.md` 的 §7 表格里解析出路径、字节数、sha256 前缀，然后**去磁盘上重新哈希那些文件**。改一句文案不会悄悄关掉它自己的检查，因为检查的输入就是文案本身。

同一套思路覆盖三份交付文档：`MEASUREMENTS.md`、一页简报的 HTML 源、演示视频的字幕与卡片。字幕面与卡片面**分开**核对——曾经把它们拼成一个字符串，结果卡片上的同一个数字救活了字幕里被改错的那个，变异测试当场抓住了这个错误。

### 7.3 变异测试

`tools/mutate-claims-test.mjs` 在临时副本里逐条改坏一个被引用的数值（23 条：容器 sha、字节数、像素计数、层直方图、截图文件名、加载耗时、简报的体积/倍率/PSNR/覆盖间隙、字幕、卡片、章节边界……），要求校验器**退出非零**并且**指名**报出对应的检查项。最后还要未变异的副本全部通过，否则说明变异装置本身坏了。

### 7.4 负例控制汇总

| 闸门 | 负例 | 期望结果 |
|---|---|---|
| 标签同步 | `FLIP_ROWS`（行序翻转） | 拒绝，并指出行数/哈希不匹配 |
| 标签同步 | `SCRAMBLE`（打乱） | 拒绝 |
| 一页简报 | 300 mm 填充物 | 渲染出 3 页，闸门报错 |
| 视频卡片 | 400 px 填充物 | 底部贴合标记消失，闸门报错 |
| 文档数字 | 23 条变异 | 逐条被指名的检查抓住 |
| 页面探针 | 4 个自检（smoke/perf/bench/opaque） | mock 下行为与页面一致才放行 |

### 7.5 时间戳口径

capture 头写本地时间（UTC+8）时就不写 UTC；写 UTC 时必须带 `Z`。曾经因为日志头打印 UTC 而本机是 UTC+8，把一个 8 小时的间隔读错了。现在文档里凡出现时刻，都写明是哪一种。

## 8. 离线链路：CBCT → 六层 → 容器

Scene B 的完整链路，全部在 CPU 上、无 GPU、无训练：

```
case.nii.gz (合成体数据)
  └─ toothfairy2_to_layers.py  --schema tf3   六层分割、1.0 mm 体素、0.6 mm splat
       ├─ web_assets/cbct_layers.ply          1,573,603 B
       ├─ web_assets/fdi_labels.bin           与 splat 行对齐
       ├─ web_assets/layer_labels.bin         与 splat 行对齐
       └─ web_assets/labels_manifest.json     产物自描述（数量、字节、sha）
  └─ tools/ply2dspk.ts --kind cbct
       └─ sceneB_from_nifti.dspk              1,748,976 B，87,405 splats，stride 20
```

三条闸门，各自独立：`npm run test:pipeline`（46 项断言，含重跑逐字节一致）、`npm run selftest:nifti`（23 项 mock，含两个反例）、`node tools/nifti-report.mjs`（把 capture 与产物对账）。容器里的 87,405 个 splat 在浏览器里被逐层单独点亮验证过：牙体 6,423 px、牙槽骨 10,579、神经管 760、牙髓 3,404、上颌窦 1,271、修复体 408，层直方图 `1:16064 · 3:59316 · 4:1293 · 6:2276 · 7:8074 · 8:382`（`MEASUREMENTS.md` §7）。

链路里踩过的四个静默失败——陈旧容器、因绝对路径与时间戳导致的不可复现、探针行号算术自相矛盾、SPA 回落把 404 变成 200——都写进了 `MEASUREMENTS.md` §7，因为它们的共同点是"不报错但结果是错的"。

## 9. 交付物，以及它们各自的闸门

| 交付物 | 生成 | 闸门 |
|---|---|---|
| 可打开的页面 | `npm run build && npm run preview` | `npm run check`（容器往返、标签同步、GPU 名解析、探针自检、文档复算、变异测试、Python 语法、`tsc --noEmit`） |
| 一页技术简报 PDF | `npm run brief` | 必须恰好 1 页（`/Count 1`）；300 mm 填充物必须翻页 |
| 60 秒演示视频 | `npm run demo` | 每帧 sha256 必须与清单一致；卡片必须 1280×720 且底部贴合标记进入成片；ffprobe 复核编码、时长、帧数 |

部署侧注意：`vite preview`（以及任何 SPA 托管）对不存在的路径会返回 `200 + index.html`。所以上线后的核对必须按**内容字节**判断，不能按状态码——这个坑在采集阶段真实发生过一次。

### 9.1 已知边界：这份文件不证明什么

- **资产是合成的。** 几何按 Teeth3DS+ / ToothFairy3 的公开统计生成，颜色与病灶位置程序化。所以 PSNR、体积、覆盖间隙量化的是**编解码与渲染的契约**，不是"训练好的 3DGS 在真实扫描上的保真度"。
- **离线链路用的是合成体数据，不是患者。** NIfTI → 六层 → 容器这段确实执行了，且逐字节可复现；但 Blender 渲染与 `postprocess_dental_gs.py` 对真实训练产物的后处理从未运行。
- **单机、单卡、单浏览器、隐藏窗口。** 全部数字来自一台 RTX 5070 Ti（ANGLE/D3D11）上的 Chromium。低端集成显卡与远程桌面未实测。
- **耗时不含合成与上屏。** `netGpuMs` 是 GPU 单遍时间，不是帧时间，也不含 CPU 合成与呈现。
- **毫米测距是水面距离。** 它基于不可见代理网格的表面交点，不是 splat 质心距离；临床含义清楚，但不能当作质心量。
- **没有任何临床诊断验证。** "拉动滑块看阻生智齿牙根是否压迫下牙槽神经管"目前只是**可做的交互**，还不是结果；神经管与牙根是否压迫需要真实病例，而当前的合成体数据里两者并不相碰。

这些边界不是免责声明，是这份文件的一部分：§10 的状态列、§7 的负例、`MEASUREMENTS.md` §9 的三处措辞，都是为了让上面每一条都能被独立复核。

## 13. 维护这份文件

- **只改仓库，不改这份文件。** 它是生成物；手改会在下一次 `--verify` 时被指出来。
- 新增核心文件时，把它加进 `tools/build-method-doc.mjs` 的分组表，并写明状态与作用，然后重新生成。
- `--verify` 会做两件事：把文件里每个代码块重新哈希，与块头记录的 sha256 比对；把块头记录的值与仓库当前文件比对。前者证明"这份文件没被改坏"，后者证明"这份文件没过期"。
- `--selftest` 证明上面两条腿都会响：先改坏一个块的字节，要求被抓住；再给一个源文件补一个换行，要求被判为过期；最后恢复并确认重新通过。
- 方法论正文在 `docs/method-doc.template.md` 里，改了正文同样要重新生成。

一句话总结这个项目的工作方式：**先把"怎么算通过"写下来，再写让它可以被算通过的代码。**
